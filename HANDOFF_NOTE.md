Приложение работает только через сервер; открытие `index.html` с диска (`file://`) не поддерживается — фронтенд ходит за данными на `/api/locales`.

## 4. Формат данных `locales.json`

Массив записей. Пример:

```json
{
  "code": "en-AU",
  "languageCode": "en",
  "countryCode": "AU",
  "flag": "🇦🇺",
  "language": { "ru": "Английский", "en": "English" },
  "country": { "ru": "Австралия", "en": "Australia" },
  "currency": "AUD",
  "tld": ".au",
  "capital": "Canberra",
  "timezones": ["UTC+10:00"]
}
```

- `code` = `<ISO 639-1 язык>-<ISO 3166-1 alpha-2 страна>`;
- `language` / `country` — названия в двух языках интерфейса `{ ru, en }`;
- `capital` и `timezones` — опциональные поля (массив таймзон, отображается первая);
- файл перечитывается сервером на каждый запрос — правки данных видны без перезапуска.

## 5. Что осталось (M3–M5)

- **M3. Рендер строк и флаги** — генерация эмодзи-флага из `countryCode`, вывод всех полей, обработка «—» для отсутствующих данных.
- **M4. Сортировка** — клик по заголовку (▲/▼), сортировка по колонкам, колонка флага не сортируется.
- **M5. Локализация, доп. поля и ошибки** — переключатель RU/EN (сейчас рендер только с `ru`), колонки «Столица» и «Таймзона» с «—», обработка ошибок сети (сообщение + «Повторить»), индикатор при нескольких таймзонах.

## 6. Принятые решения / ограничения

- Ноль npm-зависимостей; vanilla `node:http` на сервере, vanilla JS на клиенте.
- ES Modules (`"type": "module"` в `package.json`).
- Данные живут внутри бэкенда (`locales.json`), правятся вручную; внешние API в рантайме не используются.
- Флаги — эмодзи, внешние картинки не используются.
- Защита от path traversal в раздаче статики (`startsWith(ROOT)` + нормализация URL).
